# Classifier copilot

Run `npm run dev` with Node 24+ and the Codex CLI available on PATH. Sign in with `codex login` first. `CODEX_BIN` can point to an alternate Codex executable. No API key is required.

The Vite development server exposes a local `/classifier-api/chat` endpoint. Each request launches a short-lived Codex app-server over stdio using the existing local Codex account and configured model. It supplies the approved classifier and conversation, requests structured JSON, and validates the proposed definition before showing it. The conversation is kept in the current UI session; applied definitions are saved/exported with the workspace. No camera frames are sent.

Apply draft adopts a proposal; Save design persists it. Manual editing remains available under Edit definition. Requests can be stopped or retried. Changes made during a request prevent applying a stale proposal. A new conversation clears chat context without changing the definition.

This endpoint is part of the local development server, not the static production bundle. Hosted deployment requires a separately authenticated server adapter. Do not expose this local service publicly. Requests have origin, size, concurrency and timeout limits. Codex runs with read-only sandboxing, no approvals, and instructions to use no tools or hardware.

Protocol reference: https://learn.chatgpt.com/docs/app-server

## Synthetic dataset generation

Phase 04 renders 1280 × 720 PNGs from the workspace camera. Codex supplies bounded JSON scene recipes in batches of up to three; the browser validates and renders each recipe, persists it to IndexedDB, and updates the gallery. The run stops at the requested image count (1–1,000). Pause, navigate away, or close the page to stop work; completed images remain available in Saved runs. Resume uses the same workspace/calibration; a changed workspace needs a new run.

The mount pose is fixed. Each recipe sets absolute gimbal pan/tilt and a relative zoom multiplier. 1× means the saved calibrated field of view, not a hardware zoom-unit reading. The renderer uses `2*atan(tan(baseFov/2)/zoom)` and restores the original joints and lens after capture. Defaults cover pan −140..140°, tilt −30..70°, zoom 1..4×; the synthetic tilt range can be extended to 90° for calibrated installations. These are simulator controls, not commands to the physical camera or guarantees of hardware travel. Five-bin histograms expose marginal coverage; they do not guarantee exhaustive joint coverage. Wide sweeps can produce background-only images.

Live feedback aborts an in-flight planning request and discards unrendered recipes. The next request includes the latest feedback, recent recipes, readable class counts, and PTZ coverage. Already saved images are not relabeled or regenerated. The agent receives asset names, settings, and labels, not local file paths, model bytes, or live camera frames.

Assets can be dropped into the phase or added with Add files. STL and self-contained GLB are supported up to 50 MB each. Assign each asset a class, set its actual width in mm, and select Y/Z up; aspect ratio is preserved and its bottom is aligned to the slot. Models must fit a single slot. The labware library uses an existing community Corning GLB and manufacturer definition-based approximations for the Flex 200 uL filtered rack, Opentrons 10 uL non-filter rack, and candidate NEST labware. Each entry links its source and identifies its fidelity. Load labware library replaces the older generic procedural starters; historical frames retain their original asset settings. The 10 uL definition is the OT-2 product, not a claim of Flex hardware compatibility. Exact clear-labware identities are unconfirmed. See models/labware/sources.json for pinned revisions, checksums, photo evidence and mesh availability. Unknown classes are reported as lacking assets. A3 remains occupied by the modeled waste bin and is excluded from placements and labels. Collision avoidance is conservative slot-footprint checking, not a physics simulation.

YOLO export combines saved runs with the same workspace/calibration/classifier. It requires usable training and validation images and writes `images/{train,val,test}`, paired `labels/{train,val,test}` text files, `data.yaml`, source assets, and a JSON manifest. Entire runs keep their assigned split; related reruns must stay together. The YAML class ordering follows the classifier with the empty-slot class removed. Each object line is `class x_center y_center width height`, normalized to 0..1. An empty label file is a verified negative frame, not an unobserved slot. See https://docs.ultralytics.com/datasets/detect.

Labels come from two GPU silhouette passes per object at the exact image camera pose: visible silhouette with scene occlusion, and isolated silhouette for visibility. Visible pixel bounds are clipped to the image. Transparent labware is treated as solid for geometric labeling; enclosure acrylic does not occlude. These are detection boxes, not exported segmentation masks. Objects with 1-63 visible pixels or less than 25% visibility hold the entire image for review. Fully invisible objects receive no box. Legacy frames without masks also go to `images/review`, with no YOLO label file, and are excluded from data.yaml. Regenerate them to obtain labels. The Labels toggle overlays boxes on preview images. Slot polygons and conservative slot visibility remain separate occupancy metadata: obscured slots must not be treated as empty. Frame-classification and cropped slot targets require a separate conversion.

The image target counts rendered captures, including review captures; export reports usable counts for each split. Synthetic validation checks pipeline behavior, not real-world accuracy. Use separately labeled real camera sessions for meaningful evaluation. Appearance, reflectance, camera distortion, autofocus, and definition-based geometry remain approximations.

Runs and model bytes are kept in this browser's IndexedDB. Export for durable backups; browser data clearing removes local runs. The local Vite Codex endpoint is required while planning; static builds alone cannot run the agent.

## Complete deck state

Every new image records all 12 modeled deck positions A1-D3 regardless of the classifier slot subset. A3 includes the fixed waste bin. The observed state is occupied (recognizable labware), empty (unoccupied and at least 8/9 unobstructed deck samples), obscured (in-frame but blocked), or unknown (partial/outside view, missing observation, or unrecognized labware). Occupied observations can use a recognized object even when its slot footprint is cropped. Ground-truth occupancy is a separate field; it never overrides an uncertain observation. Visibility is a conservative nine-ray estimate, not a pixel mask of the deck. Legacy images report all twelve states as unknown until regenerated.

The preview shows a twelve-cell state grid. Export adds a `deck-state/<image>.json` report for every image, including legacy images. New images additionally get `slots/images/<split>` and `slots/labels/<split>` pairs with projected deck-region boxes and fixed class IDs: 0 occupied, 1 empty, 2 obscured, 3 unknown. Missing or behind-camera projections have no box but retain their unknown JSON state. `slots/data.yaml` is included when new slot-state images exist in both train and validation. These slot labels are separate from labware detection boxes in the root dataset. Use calibrated deck geometry to associate detections with stable slot IDs; absent predictions must resolve to unknown, never automatically empty. No trained live-camera inference is implemented by this synthetic labeling stage.

New runs default to Lock calibrated view & lighting: pan/tilt are fixed to the workspace joint readings, relative zoom is 1, exposure multiplier is 1, and warmth offset is 0. Uncheck the lock to intentionally enable sweeps. Existing runs retain their original ranges. Workspace view.cameraPtz records connected hardware pan/tilt, raw zoom, and device name for runtime reuse; synthetic relative zoom is not the hardware raw zoom value. Recalibrate after moving the mount or changing hardware zoom.
